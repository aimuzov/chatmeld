# Chat adapter

Адаптер личных аккаунтов Telegram, MAX, WhatsApp и VK для своего мессенджера.
Telegram подключается через MTProto по телефону или QR, MAX и WhatsApp через QR.

Нужен Node.js 24+. Зависимости закреплены в package-lock.json.

## Запуск

```sh
npm ci
cp .env.example .env
```

Получи `api_id` и `api_hash` на [my.telegram.org](https://my.telegram.org/apps)
и заполни `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` в `.env`.
Номер телефона можно ввести при входе.

```sh
npm start -- login
npm start -- chats
npm start -- listen
```

Если код не приходит, попробуй вход через QR:

```sh
npm start -- login --qr
```

Открой Telegram на телефоне: Настройки, Устройства, Подключить устройство.
Сканируй QR из терминала и подтверди вход. Если включена 2FA, введи пароль
в терминале. QR обновляется автоматически; Ctrl+C отменяет ожидание.

`login` сохраняет сессию в `.data/telegram.session`, если использован пример `.env`.
Код и пароль вводятся скрыто. Сессия даёт доступ к аккаунту: файл создаётся
с правами 600 и исключён из Git вместе с `.env`. Отозвать сессию можно в Telegram
в разделе устройств. Один файл сессии используй только в одном процессе.

`chats` показывает ID чатов. `listen` выводит новые входящие сообщения
в формате JSONL. Фильтр принимает точный ID из списка чатов:

```sh
npm start -- listen --chat=123456789
npm start -- send --chat=123456789 --text='Привет'
```

`send` отправляет текст от твоего имени. Сам по себе запуск проекта ничего не отправляет.

## MAX

Для MAX нужен [uv](https://docs.astral.sh/uv/). Он установит Python 3.12+
и зависимости из отдельного lock-файла. Настройки Telegram для MAX не нужны.

```sh
npm run setup:max
npm start -- login --provider=max --qr
npm start -- chats --provider=max
npm start -- listen --provider=max
npm start -- send --provider=max --chat=123456789 --text='Привет'
```

Открой сканер QR в MAX на телефоне, отсканируй код из терминала и подтверди
вход. Если включён пароль, программа попросит его в терминале.
Если QR истёк, запусти login повторно. Ctrl+C отменяет ожидание.

Сессия хранится в `.data/personal.max.db` с правами 600. Для другого аккаунта
используй `--account=work` или отдельный `MAX_SESSION_FILE` в `.env`.
Сессию MAX используй только в одном процессе.

Провайдер использует [PyMax 2.5.0](https://github.com/MaxApiTeam/PyMax)
и внутренний API MAX. Совместимость зависит от изменений MAX.
Список чатов объединяет кеш входа и ответ fetch_chats; старые чаты могут
не попасть в него, если сервер отдаёт их отдельными страницами.
При обрыве соединения процесс завершается с ошибкой, автоматического
переподключения пока нет.

## WhatsApp

Зависимости WhatsApp устанавливаются вместе с Node-проектом, Python ему не нужен.

```sh
npm ci
npm start -- login --provider=whatsapp --qr
npm start -- chats --provider=whatsapp
npm start -- listen --provider=whatsapp
npm start -- send --provider=whatsapp --chat=79990000000@s.whatsapp.net --text='Привет'
```

На телефоне открой WhatsApp, Связанные устройства, Привязка устройства.
Отсканируй QR из терминала и подтверди вход. QR обновляется автоматически.

Адрес для отправки бери из поля `id` в `chats`. WhatsApp использует телефонные
адреса, LID и адреса групп. Адаптер сохраняет адрес как вернул его WhatsApp.
Имя берётся из контакта, для группы используется её название.

Сессия хранится в `.data/personal.whatsapp/`. Папка имеет права 700,
файлы сессии и каталог чатов имеют права 600. Путь можно изменить через
`WHATSAPP_SESSION_DIR`; для другого аккаунта есть `--account=work`.
Одна папка сессии используется только одним процессом. Устройство можно
отвязать в WhatsApp на телефоне. `disconnect` закрывает соединение,
сохранённая сессия при этом остаётся.

WhatsApp передаёт список чатов и контактов при синхронизации с телефоном.
Адаптер сохраняет каталог между запусками. Если сразу после входа список
пустой или неполный, оставь `listen` запущенным и дождись синхронизации.
При подключении `listen` отдельно загружает имена контактов. Команда `chats`
читает локальный каталог без второго соединения, её можно запускать рядом с `listen`.
История сообщений не пересылается во входящий поток.

Провайдер использует [Baileys 7.0.0-rc14](https://github.com/WhiskeySockets/Baileys).
Перезапуск соединения после QR-привязки обрабатывается автоматически.
При последующих сетевых обрывах команда завершается с ошибкой.

## VK

Для личной переписки нужен пользовательский access token с доступом к
Messages API. Его можно получить через QR-вход веб-клиента или ввести вручную.
Токен сообщества не подходит. Доступ к сообщениям проверяется до сохранения сессии.

```sh
npm run setup:vk-qr
npm start -- login --provider=vk --qr
```

Откроется изолированный невидимый Chromium. QR со страницы VK появится
в терминале. Отсканируй его камерой или сканером в приложении VK
и подтверди вход на телефоне. Если VK покажет на телефоне шестизначный код,
введи его в терминале по запросу. При неверном коде программа попросит ввести его
ещё раз. Если QR обновится, программа покажет новый.
Вручную копировать токен не нужно. Ctrl+C отменяет ожидание и закрывает браузер.
Сохранённая сессия записывается только после проверки доступа к переписке.

Браузер нужен только для QR-входа. При обычной работе используются API
и сохранённый токен. Cookies и профиль браузера не сохраняются.
Если VK изменит страницу входа или запросит дополнительную проверку,
QR-вход может не завершиться; токен по-прежнему можно ввести вручную.

```sh
npm start -- login --provider=vk
npm start -- chats --provider=vk
npm start -- listen --provider=vk
npm start -- send --provider=vk --chat=123456789 --text='Привет'
```

При входе введи токен в терминале, ввод скрыт. Можно указать его через
`VK_ACCESS_TOKEN` в `.env`. Не передавай токен аргументом команды или в чат.
Программа проверяет личный аккаунт и чтение диалогов до сохранения токена.

Если у тебя есть своё приложение, поддерживающее Implicit Flow и доступ
к Messages API, укажи `VK_APP_ID` в `.env`. Команда login напечатает ссылку
OAuth VK. После подтверждения доступа вставь полный адрес результата
авторизации в терминал; программа проверит state и извлечёт токен.
Без подходящего токена VK-провайдер не сможет читать личные сообщения.

Сессия хранится в `.data/personal.vk.json` с правами 600. Путь можно изменить
через `VK_SESSION_FILE`, для другого аккаунта есть `--account=work`.
Файл исключён из Git. После отзыва или истечения токена выполни login заново.

Список чатов показывает имена и фамилии пользователей, названия сообществ
и бесед. Для отправки бери точный `id` из списка, в том числе отрицательные ID.
Входящие получает User Long Poll v19. После сбоя long poll, который сервер
не может продолжить, события за время разрыва могут быть потеряны:
восстановление истории пока не реализовано.

Провайдер использует [vk-io](https://github.com/negezor/vk-io).
Типы пользовательских токенов и методов описаны в
[официальной схеме Messages API](https://github.com/VKCOM/vk-api-schema/blob/master/messages/methods.json).

## Подключение своего мессенджера

```sh
npm start -- listen --webhook=http://localhost:3000/messages
```

Для постоянной настройки есть `WEBHOOK_URL` и `WEBHOOK_TOKEN` в `.env`.
Для MAX, WhatsApp или VK добавь соответствующий `--provider` к команде `listen`.
Токен передаётся как Bearer. Получатель должен ответить кодом 2xx за 10 секунд.
После успешной доставки сообщение также выводится в stdout.
Для чистого JSONL без служебных строк npm запускай `npm run --silent start -- listen`.

```json
{
  "provider": "telegram",
  "accountId": "personal",
  "chatId": "123456789",
  "messageId": "123456789:42",
  "senderId": "123456789",
  "direction": "incoming",
  "text": "Привет",
  "sentAt": "2026-11-02T12:00:00.000Z",
  "attachments": []
}
```

Ключ сообщения у получателя: `provider + accountId + messageId`.
Для ответа используй `chatId` с командой `send` или методом `sendMessage`.

## Устройство

Общий контракт находится в `src/core/provider.ts`, реестр аккаунтов
в `src/core/registry.ts`, Telegram-клиент в `src/providers/telegram/`.
Новый мессенджер реализует `MessagingProvider` и регистрируется в CLI.
Идея разделения взята из адаптера pufikmebel; зависимости от CRM здесь нет.

Для другого аккаунта укажи `--account=work` и отдельный
`TELEGRAM_SESSION_FILE`. Для нескольких аккаунтов запускай отдельные процессы.

Telegram подключён через [teleproto](https://docs.teleproto.dev), продолжение
архивного GramJS. [Вход по телефону](https://core.telegram.org/api/auth).

## Границы примера

Поддержаны облачные чаты, новые входящие сообщения и отправка текста.
Вложения передаются как типы провайдера, без скачивания файлов.
История, секретные чаты, правки, удаления и отправка файлов не реализованы.
Сообщения сервисного аккаунта Telegram с кодами входа не передаются.

Доставка без постоянной очереди и повторов. При сбое webhook или переполнении
очереди процесс завершается с ошибкой; недоставленные события не сохраняются.
Это пример интеграции, для постоянной работы нужны outbox и восстановление истории.

## Проверки

```sh
npm test
npm run check
npm run test:max
```

Тесты проверяют нормализацию сообщений, права файла сессии и HTTP-доставку.
Вход в реальный аккаунт проверяется отдельно.
